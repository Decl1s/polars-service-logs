# Журналы сервисов на Polars

[Релиз 0.1.0 и архив](https://github.com/Decl1s/polars-service-logs/releases/tag/v0.1.0) · [Проверки CI](https://github.com/Decl1s/polars-service-logs/actions)

Я разработал учебный конвейер на Polars: преобразую синтетические JSONL-журналы
в очищенные разделы Parquet и почасовую статистику времени ответа и HTTP-ошибок.
Основная новая технология — Polars 2.0.0. Все объяснения и сообщения — на русском.

[Подробный конспект](NOTES.md) · [Технологии](TECHNOLOGIES.md) · [Проверки](VALIDATION.md)

## Запуск за несколько минут

Нужен Python 3.11 или 3.12 и поддерживаемый бинарным пакетом Polars процессор.
Создайте окружение в каталоге проекта:

```sh
python -m venv .venv
```

Linux: `source .venv/bin/activate`.
Windows PowerShell: `.venv\Scripts\Activate.ps1`.
Если активация запрещена, используйте `.venv\Scripts\python.exe` вместо `python`.

```sh
python -m pip install --only-binary=:all: -r requirements.txt
python -m logs_pipeline demo
python -m logs_pipeline run
```

Откройте `workspace/output/preview.md` в редакторе с просмотром Markdown.
Ожидаются 10 105 входных строк, 10 000 уникальных запросов, 100 дублей,
5 отклонённых строк, 3 даты UTC, 150 почасовых групп, 500 ошибок 5xx и 500 ошибок 4xx.

## Что посмотреть

| Файл | Назначение |
| --- | --- |
| preview.md | Русская сводка по сервисам и причинам ошибок |
| events/date=YYYY-MM-DD/part.parquet | Очищенные уникальные события по дате UTC |
| hourly.parquet и hourly.csv | Почасовая статистика по сервисам |
| quality.json | Накопленные причины отклонения в текущем снимке |
| manifest.json | Хэши источников, итоговые показатели и контрольные суммы файлов |

Показатели: число запросов, ошибки 5xx, отдельные ошибки 4xx, доля ошибок сервера,
среднее время, p95 с линейной интерполяцией и число медленных запросов.
Медленный запрос по умолчанию — от 500 мс включительно.

```python
import polars as pl

hourly = pl.read_parquet("workspace/output/hourly.parquet")
print(hourly.sort("p95_duration_ms", descending=True).head(5))

events = pl.scan_parquet("workspace/output/events/**/*.parquet", hive_partitioning=True)
print(events.select(pl.len()).collect())
```

## Как проверить

```sh
python -m logs_pipeline run
python scripts/smoke_check.py
python -m unittest discover -s tests -v
python scripts/check_public.py
```

Каждый запуск полностью пересобирает снимок. Повтор не добавляет данные к прошлым
выгрузкам: количество запросов и статистика сохраняются. Удаление входного файла
удаляет его события из следующего снимка. История версий входных файлов не ведётся.

Попробуйте другую границу медленного запроса:

```sh
python -m logs_pipeline run --slow-ms 1000
python -m logs_pipeline run --json
```

В отдельном синтетическом файле повторите код события с другим временем ответа.
Ожидается ошибка конфликта, прежняя выгрузка сохраняется. Не проверяйте это
редактированием настоящих рабочих журналов.

## Контракт входа

Одна строка JSONL — один объект. Дополнительные поля или неверные JSON-типы отменяют
весь запуск. Отсутствующие обязательные значения и неверные бизнес-значения учитываются
как ошибочные строки и не попадают в витрину.

| Поле | Тип JSON и правила |
| --- | --- |
| event_id | Строка LOG- и 8 цифр; одинаковый код допускает только одинаковое событие |
| timestamp | Строка UTC в формате YYYY-MM-DDTHH:MM:SSZ |
| service | Строка api, worker или gateway |
| status_code | Целое число 100…599; строки с числом и true/false запрещены |
| duration_ms | Конечное число 0…60 000; строки с числом запрещены |

```json
{"event_id":"LOG-00000001","timestamp":"2026-10-01T10:15:00Z","service":"api","status_code":200,"duration_ms":125.5}
```

Для своих входных данных укажите другие папки:

```sh
python -m logs_pipeline run --input workspace/my-input --output workspace/my-output
```

## Ограничения и приватность

Пределы: 100 файлов, 8 МиБ на файл, 32 МиБ суммарно, 100 000 записей и 366 дат UTC.
`collect(engine="streaming")` используется для выполнения ленивых выражений,
но итоговая таблица остаётся в памяти. Проект не обещает обработку произвольного объёма.

Результат готовится во временной папке и заменяет только помеченную выгрузку проекта.
Посторонние файлы и символические ссылки в папке результата блокируют замену.
Откат при обычной ошибке записи проверен; общей файловой транзакции и защиты от
аварии питания нет. Не запускайте одновременно несколько процессов записи.

Генератор не читает документы, профиль, IP, URL или данные пользователей.
Локальные входы, Parquet, отчёты и окружение исключены из Git и исходного архива.
Состав публикации задаёт `PUBLIC_FILES.txt`; проверка ищет контакты, типичные секреты
в исходниках. Адреса авторства вне домена no-reply вызывают примечание,
не блокирующее сборку: метаданные коммитов видны в публичной истории Git.
Сам адрес проверка не печатает, история Git в ZIP не входит.
Реальные журналы и полученные из них результаты
могут содержать чувствительные сведения: их нельзя автоматически публиковать.
